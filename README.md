# AI-Powered Orbital Traffic Management System

## Files

| File | What it is |
|---|---|
| `data.csv` | Raw orbital-object catalog (input data) |
| `orbital_traffic_model.ipynb` | Full ML pipeline: cleaning, feature engineering, risk labeling, Random Forest training, evaluation |
| `app.py` | Streamlit dashboard — the interactive front-end using the trained model |
| `risk_model.pkl`, `orbital_data_processed.csv`, `band_counts.pkl` | Artifacts generated by the notebook, loaded by `app.py` |
| `requirements.txt` | Python packages needed |

## How to run (in VS Code)

1. Open this folder in VS Code.
2. Install dependencies:
   ```
   pip install -r requirements.txt
   ```
3. **Run the notebook first** (`orbital_traffic_model.ipynb`, Run All) — it produces the three
   artifact files the dashboard needs. It's already been run once, so the artifacts exist, but
   re-run it if you change anything.
4. Launch the dashboard:
   ```
   streamlit run app.py
   ```
   It opens in your browser automatically.

## How the ML part works (for explaining to your professor)

The raw catalog has orbital parameters (Perigee, Apogee, Inclination, object type, size) but
**no ready-made "risk level" column** — so a rule-based **Risk Score** was engineered from three
things that genuinely relate to collision risk:

- **Congestion** — how many active objects already share that orbital region (LEO/MEO/GEO/HEO)
- **Object type** — debris and rocket bodies are riskier than active, maneuverable payloads
- **Size (RCS)** — bigger objects are a bigger and more damaging collision target

That score is bucketed into **Low / Medium / High / Critical**, and a **Random Forest Classifier**
is trained to predict this label from just `PERIGEE`, `APOGEE`, and `INCLINATION` — the three
numbers a mission planner would actually enter for a *new, proposed* orbit. The model never sees
object type or size directly, so it has to genuinely learn the geometry-to-risk relationship
rather than just repeating the formula.

**Result:** ~82% test accuracy overall, strong on Low/Critical, weaker on Medium — a real class-
imbalance limitation worth mentioning if asked, not a bug.

## Dashboard modules (in `app.py`)

- **Risk Assessment** — runs the trained model on the sidebar inputs
- **Orbital Congestion Analysis** — active-object counts per region
- **Orbit Recommendation Engine** — compares average risk across regions
- **Launch Window Planning** — simplified congestion-based go/no-go message
- **Orbital Sustainability Score** — combines congestion + risk into one 0–100 score
- **Debris Priority** — top tracked debris in the selected region, ranked by risk
- **Orbit Copilot** — rule-based Q&A that explains the results in plain language (no external
  API/API key needed — good for an offline classroom demo)
